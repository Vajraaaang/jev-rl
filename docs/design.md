# Recovery Lab v2 implementation contract

The first experiment is preserved under `artifacts/baseline`. V2 is a research platform for a partially observed recovery agent, not a production remediation daemon. Only the local controller learns; hosted Jev is a pinned diagnostic sensor. Defaults never call hosted APIs.

## Boundaries

`scenarios.py` supplies frozen `Incident` records and deterministic `generate_suite(split, count, seed)` with disjoint train/validation/test wording and reserved test combinations. Incident fields: `id: str`, `faults: tuple[str, ...]`, `wording: str`, `seed: int`, `dependency_ready_at: int | None = 8`, `relapse_after: int = 4`, `max_ticks: int = 48`, `verification_ticks: int = 12`, `restart_duration: int = 2`, `log_variant: int = 0`, `noise: bool = False`. Causes remain credentials, connections, dependency; variants exercise permanent dependencies, delayed recovery, noise and relapse. Verification exceeds the maximum generated relapse window; connections incidents reject an insufficient custom window. Unknown inputs fail validation.

`sandbox.py` supplies `IncidentEnv(incident, advisor=None)`. `observation()` returns a JSON-compatible dict containing only public evidence: schema_version, tick, remaining_ticks, health, healthy_streak, evidence (logs, config, connections, dependency, diagnosis), last_action, last_outcome, action_counts. Unknown evidence is null. There is no fault tuple, scenario id, seed or wording label in this observation. `step(action: str)` returns `(observation, reward, done)`. Actions are logs, config, connections, dependency, jev, restart, rollback, wait, stop, escalate. Jev requires previously collected logs. Every action costs simulated time. Stop independently verifies sustained health within the deadline; escalate ends unrecovered. Diagnostic failures become observed unavailability and have costs; they never become success. Metrics are exposed through `metrics()` and contain recovered, actions, downtime_ticks, interventions, unnecessary_interventions, tool_cost_units, api_cost_usd, input_tokens, api_calls, cache_hits, reward, termination, safety_violations. Structured trace events preserve observations before/after, outcome, action, tick, reward components and provider provenance. Hidden simulator state is accessed only by independent evaluator/oracle code.

`agent.py` supplies `RecoveryAgent(policy, max_interventions=6)`, `decide(observation)->Decision` and `run(env)->dict`. Decision has action, reason, evidence, hypotheses. Agent passes a defensive copy of public observations to policy.select(observation), enforces supported tools, prevents consult-before-logs, repeated evidence loops and intervention budget violations, and emits decision traces. `ChecklistPolicy`, `RandomPolicy(seed)` and `GreedyRepairPolicy` expose select(observation). Reasons are concise decision summaries, not model chain of thought.

`learning.py` supplies `LinearQPolicy(use_jev=False, seed=0)`, select(observation), save(absolute_path), load(absolute_path), and `train_policy(incidents, episodes, seed, use_jev, advisor=None)->(policy, training_summary)`. Feature-based Q-learning generalizes evidence combinations; identical training episode budgets and seeds are used across arms. Frozen evaluation never mutates weights. Serialization includes feature schema and digest validation. Admissible action masks require logs before consultation and sufficient remaining budget for verification. Held-out data never enters training or checkpoint selection.

`benchmark.py` supplies `run_benchmark(output: Path, episodes=4000, count=60, seeds=(11,22,33), advisor_mode='offline', cache_path=None)->dict`, `audit_run(output)->dict`, and `replay_run(output)->dict`. It trains two arms, evaluates checklist, random, greedy repairs, RL without advisor, RL with advisor, and corrupted diagnostic ablation against paired immutable scenario manifests. It saves report.json, manifest.json, episodes.jsonl, checkpoints and human-readable report.md. Report includes observed metrics, per-seed results, paired intervals with resampling unit described, cause diagnostic Brier/multilabel metrics separate from recovery, advisor provenance, file SHA256s, environment/config/version metadata and total acquisition costs. Report wording must distinguish heuristic, corrupted, cached hosted and hosted results. Oracle is an explicitly privileged upper-bound analysis and never a deployable competitor.

`service.py` preserves existing demonstration routes and adds a dashboard plus independent v2 sessions through GET /api/meta, POST /api/incidents, GET /api/incidents/{id}, POST /api/incidents/{id}/step, POST /api/incidents/{id}/run, GET /api/report. Incident creation accepts faults, wording, seed; defaults offline. The server binds localhost, serializes mutations, bounds bodies/session count, validates JSON and returns useful 400/404/409 errors. Step action and run policy (checklist, rl_without_jev, rl_with_jev) are explicit. Responses contain id, observation, metrics, trace, done. Checkpoints load only from configured benchmark output; no arbitrary user-supplied filesystem path is accepted. Web assets are package data served from an absolute package directory. Dashboard clearly labels the simulator and advisor source.

## Verification and deliverables

Preserve v1 commands and measured evidence. Add v2 benchmark, replay, audit and dashboard commands, meaningful invariant/security/regression tests, local browser-visible proof, CI, packaging, reproducible example config, architecture/evaluation/model-card docs and an executed v2 comparison. Any limitations in learned recovery and domain transfer are reported directly. No claim of world-class empirical performance follows from implementation quality alone.
